# PseudoForge final release plan

This plan targets `v1.4.0`. The published `v1.3.7` tag points to `80e8aaf`. The historical development baseline is `39ca4b2` on `codex/physics-controls-and-design`. The branch supports [native manual generation for all nine engines](../how-to/manual-generation.md) and [reference-constrained design](../how-to/reference-design.md) with grid, random, uniform, adaptive and conditional Bayesian search using Quantum ESPRESSO (QE).

The native panel covers one baseline and two variants per generator. Follow-up experiments include Si EOS comparisons, a CP2K/GTH grid and basis ladder, ABINIT/fhi98PP and OpenMX/ADPACK consumer checks, completed Ti/O factorial swaps and QE pressure against an independent all-electron EOS. A separate force pilot checks PySCF basis and integration-grid convergence before producing QE reference cases. Local QE search supports orderly pause and resume, elapsed budgets with one-CPU affinity, and separate accounting for child CPU time, setup and held-out checks. The full independent material benchmark and scheduler-level budget enforcement remain release work.

The release will deliver one workflow from physical specifications to a tested candidate or portfolio of candidates, with reproducible inputs, diagnostics, measured downstream cost, and the tested range of applicability. The CPC submission has a separate scientific completion criterion. It requires a result about when the combined method improves the design process on independent references. The [research proposal](engine-portfolio.md) records the related work in more detail.

## 1. Complete the native generation contract

Reuse `data/physics-controls.tsv`, `lib/physics.sh`, existing adapters and complete native decks. The capabilities reflect the executable version and the prepared input layout. Record formalisms, XC, relativity, core/valence configurations, channel bounds, units, coupled fields, output formats and verified consumers. Expose explicit reasons for a control being unavailable. Numeric parameters may be continuous or integer, and structural choices have their own allowed values and coupled deck edits. Start from existing defaults, upstream examples and working profiles for each supported physics combination.

| Generator | Controls and behaviors to verify and extend |
| --- | --- |
| `ld1` | Reference charge, occupations and semicore, NC/US/PAW construction, local and channel radii, projector cards, NLCC and augmentation settings |
| `oncvpsp` | Channel radii and reference energies, local potential, `qcut`, `ncon`, `nbas`, number and separation of projectors, NLCC and independent configurations |
| `uspp` | Paired AE/PS decks and fixed-width records, occupation and projector consistency, channel/local/core and augmentation radii, SCF settings |
| `fhi98pp` | TM/Hamann, explicit channel radii and energies, pseudocore correction, occupations and relativity. Verify explicit-radius behavior when the native default radius is implicit |
| `opium` | Native pseudization and optimization settings, valid state/channel decks, local/core sections, XC/relativity, output headers and independent configurations |
| `gth` | Fit the atomic reference, Gaussian coefficients/radii, reference weights and free/fixed masks via the full fitting bundle. Record coefficient import and fitting as distinct operations |
| `atompaw` | Coupled matching/local/augmentation radii, semicore, extra projector count and energies, pseudization, compensation shape and dataset formats |
| `ape` | Orbital/core blocks, per-component matching, native methods, relativistic solver, local channel and NLCC, numerical tolerances and fallback provenance |
| `adpack` | Native parameter arrays, occupation/SCF/grid limits, solver, channel/local/core controls, projectors, ghost-search result and strict generation policy |

- For every supported field, check that a change reaches the intended native record and that invalid combinations fail before execution. Run real default and modified inputs per engine. Compare requested and realized physics. Test output parseability in a compatible reader, native-format negotiation, repeated preparation, external input round trips and archive checksums.
- Check installed engine coverage and existing profiles such as PSlibrary high/low, SG15 and PseudoDojo. Verify library reproduction where applicable. Make fallback explicit, including any Libxc retargeting. Changes to XC, valence partition, relativity, engine or formulation during search are either an allowed replicated decision or a separate attempt with their own identity.
- Distinguish generation success, valid file, atomic verification and material verification. Record outcomes for bound and scattering ghosts, nonconverged diagnostics, matching and overlap, nonfinite results, timeouts and runtime errors. Reject a diagnosed bound ghost in release-quality output. Report the scope and energy range of every diagnostic.
- Keep native files immutable per attempt. Retain the exact binary/version, input hashes, records of overrides, build flags and source/patch identity. Publish validated artifacts atomically. Give retries and concurrent executions separate scratch space, retain failure logs and clean up child processes on cancellation.

## 2. Build the evaluation and optimizer

Extend `tools/pf_design.py` and keep existing protocol and finite-grid execution compatible. Use the Bash core for generation and shared command validation. Introduce a versioned protocol for the scientific target, allowed engines and controls, starting profiles, tolerances, reference and structure splits, search budget, seed, data fingerprints and execution limits. Use a shared result schema across the CLI, TUI, API and browser. Record parameters in native units and observables in agreed units.

1. **Evaluate the starting point.** For each supported engine and starting profile, generate or resolve the declared baseline. Use the same target, evaluator, tolerances and convergence protocol for baseline and tuned candidates. Preserve the baseline in the comparison even when it fails. A profile that already passes can be returned when the budget produces no useful improvement.
2. **Evaluate the constructed operator.** Check native atomic configurations, orbital and logarithmic-derivative errors and ghosts over a declared energy range. Measure false rejections by sending a sample of screened candidates to material evaluation. Material scores use independent converged references for relative energies, forces and stress, plus EOS or additional application-specific observables when references support them. Validate energy differences within compatible composition and reference conventions.
3. **Measure convergence separately.** Scan cost-relevant consumer settings. For QE, measure `ecutwfc` and `ecutrho` where applicable, along with k-point, smearing and SCF convergence controls. For localized bases, measure basis, integration grid and other relevant errors. Derive the recommended settings from an explicit error allowance, with tight-setting checks at representative conditions. Store atomic generator quantities such as ONCV `qcut`, physical matching radii and consumer cutoff as distinct fields.
4. **Tune each engine.** Add deterministic replay, seeded random and conditional Bayesian search under common constraints and a common budget. Include continuous channel radii and energies, discrete projector count, local channel, semicore and other native controls from milestone 1. Allow declared discrete choices such as NLCC, compensation charge, augmentation and pseudization method where documented and tested. Screen infeasible coupled combinations. Record which strategy proposed each attempt, why it was skipped or rejected, and the result of re-evaluation. Keep a Pareto set for feasible error/cost trade-offs.
5. **Track usable cost.** Record allocated core-hours and wall time for setup, construction, failed attempts, fitting, validation and search overhead. Record CPU time separately when available. Record downstream time and resources for a representative workload under fixed hardware and parallel settings. Report equal-accuracy savings and the number of equivalent runs required to recover the one-time search cost when there is a measurable saving. Show the assumptions behind that estimate.

Use a resumable trial ledger with immutable inputs, atomic state transitions and budget enforcement across concurrent workers. Record seeds, candidate order and acquisition decisions. Cache only matching inputs, executables, references and numerical settings. Count cache and setup costs consistently between benchmark methods. Exercise cancellation, retry accounting, resume after interruption, run replay, duplicate work and malformed protocols.

## 3. Allocate across engines and repair material failures

- **Adaptive selection.** Search a conditional space of compatible generator, NC/US/PAW formulation and native parameter choices. Preserve analytic and other native representations in their own compatible tracks. Start with equal allocation and a cost-aware conditional optimizer as comparators. Give the adaptive scheduler evidence from feasibility, remaining error margin, estimated improvement and evaluation cost. Compare single- and multi-fidelity evaluation only where atomic and material stages support calibrated decisions. Keep every compatible branch eligible and account for exploration cost.
- **Tested domain.** Use predefined material families and sample off-equilibrium states such as volume compression, strain and atomic displacement. Add selected challenge structures near observed failures within a declared budget. Map the sampled conditions, observables, tolerances, failed cases and coverage gaps. Reserve independent families and their reference results for a final assessment. Store what was evaluated for each candidate instead of extrapolating to unseen pressure ranges or chemistries.
- **Physical diagnosis and intervention.** First separate numerical convergence, incompatible physics, generation failure and material-level disagreement. On suitable failures, plan matched trials for semicore, channel radius, projector count/energy, local channel or formulation. Preserve the original and vary a controlled set of inputs. Report the particular case improved, change in error, new failures and incremental cost. Recheck proposed repairs against neighboring cases and evaluate the selected version on the untouched test split.
- **Optimize a set of potentials.** For a multielement material, keep the geometry, functional and numerical settings matched. Start with all baseline, one-element swaps and combined swaps. Measure the change in each observable and whether combined swaps deviate from the sum of single swaps under those conditions. Use prioritized subsets and follow-up pair tests when there are too many combinations. Feed those results into the search over which element, generator and parameter to try. Compare against independently tuning each element at the same total budget. Test for error cancellation by scoring the selected set in a chemical environment outside the training families. Treat observed swap effects as conditional evidence, with uncertainty.

## 4. Validate all nine pathways and manage source changes

Start the integration pilot with a verified QE/UPF path spanning NC, US and PAW. Bring GTH into CP2K with basis convergence and a systematic same-operator comparison where possible. Evaluate ADPACK via a verified native consumer such as OpenMX once the dataset and basis workflow is confirmed for the chosen release. Verify native export and consumption for the remaining adapters by reading the actual dataset through a compatible, documented solver. Use PSML or other conversion only when operator equivalence is demonstrated for the specific exporter and consumer.

For each of the nine engines, deliver a real run comparing default versus tuned with the pinned configuration and publish its level of evaluation. Track atomic optimization, native consumer loading, compatible material evaluation and independent reference coverage separately. Any unsupported engine/representation/XC/relativity/consumer combination has an explicit matrix entry and reason. When cross-code comparisons use differing basis representations, estimate numerical/basis error independently before pooling material accuracy results. Compare runtime within a specified backend and workload. Keep differing backends separate where implementation or hardware effects cannot be controlled. Document practical installation and reference-data blockers early.

Keep the stock source pinned. Start by collecting existing log evidence. If diagnostics are insufficient, add targeted, versioned instrumentation for channel-resolved scattering, ghost search results, overlap, matching, conditioning or solver failures. Evaluate whether it reduces expensive material trials and measure false rejections. If a reproducible physical or numerical bottleneck remains, prototype one targeted upstream change at a time, for example a multi-energy objective or a supported projector extension. Enforce the equations and constraints of that formulation. Compare stock tuned versus patched tuned under the same budget. Merge changes that fix a demonstrated defect or earn an evidenced advantage without unacceptable regressions.

Implement approved changes as small pinned patches with source hashes, licence/redistribution checks, compiler and dependency records, diagnostics and physics tests. Build them reproducibly and identify the resulting engine variant in every run. The search may select a known engine variant. It uses parameters, recipes and these versioned variants for reproducible trials. Use the existing OPIUM patch pattern where it fits and submit generally useful fixes upstream where practical.

## 6. Lock the benchmark and complete the release

### Benchmark protocol and manuscript

- Pilot on a tractable family such as Ti/O, including elemental environments, oxides, compression and displacements. Use the pilot to validate reference acquisition and estimate compute cost. Before the full experiment, freeze the elements/compounds, geometries, train/validation/test partitions by chemical or structural family, XC, spin/relativistic conventions, independent all-electron references and tolerances. Freeze the minimum practically meaningful benefit and the analysis procedure before seeing test results. Extend to families with different bonding and semicore needs as references permit. Keep geometrically similar structures in the same split.
- Use published all-electron EOS values for compatible EOS observations, and produce or obtain separately converged reference forces/stresses on the required distorted structures. Document basis, k mesh, smearing and reference uncertainty below the tolerance assigned to pseudopotential error. Document checks of compatible relative-energy conventions across dataset types. Legacy results against a surrogate potential remain labeled as such.
- Compare defaults per engine, tuned fixed-engine designs selected using training data, a finite grid, seeded random, uniform engine allocation, conditional cost-aware optimization and the full adaptive method. Include appropriate published baselines such as SSSP/PseudoDojo in compatible runs. Compare independent element tuning against joint tuning. Ablate diagnostic screening, budget allocation, domain challenge sampling and repair. Compare any proposed generator modification with its stock tuned counterpart.
- Use equal total core-hour budgets for search strategies and document the hardware, charges for failures and any timeouts. Repeat stochastic searches with registered seeds. Report success rate, compute to reach target, best feasible cost at a fixed budget, downstream time at equal tolerances and uncertainty across seeds and material groups. Include censored runs, outliers and cases where the baseline is preferable. A candidate stays selected before the independent test is opened. Report all predeclared held-out cases.
- **Scientific completion criterion.** Support the paper's main claim with a practically meaningful held-out advantage over the strongest appropriate equal-budget baseline, with uncertainty and negative results. A result can demonstrate higher probability of meeting the target, lower search cost to reach it or a better accuracy/cost trade-off at the same budget. Demonstrate separately whether joint interventions and any engine patches add value. Revise the claim or run a new preregistered experiment on a fresh independent split if the evidence fails the criterion. Release software-quality and article-quality decisions separately.
- Cite Hansel et al. for automated PAW fitting, García et al. for PSML, van Setten et al. for PseudoDojo, Yamashita and Shiihara for ADPACK Bayesian fitting, as well as ONCV optimization, SSSP, Bosoni et al., UZH, element-resolved molecular testing and the applicable engine papers. Use the attached PDFs as scientific references. The attached manuscript brief records historical feature claims. Reverify test counts, coverage, platform inventory, timed runs, ghost policy and workarounds against the release evidence before putting any of those claims in the article.
- Prepare `main.tex`, the journal's Program Summary and bibliography, reproducible figure/table scripts, architecture and physics workflow diagrams, the generator/consumer matrix, benchmark comparisons, a data and code availability statement, licence information and the compiled submission PDF. Discuss the selection method, physical use case, test results, comparison boundaries, failures and reproducibility. Run the manuscript build from clean sources and generate every plotted result from archived data. Verify the [CPC scope and current author requirements](https://shop.elsevier.com/journals/computer-physics-communications/0010-4655) before packaging for the Computer Programs in Physics submission path.

## Start here

Run the baseline gates and build a small QE pilot with pinned starting profiles, NC/US/PAW representation coverage and independent reference inputs. Then implement the protocol and ledger around the existing grid so that a fixed-engine tuned-vs-default comparison and an equal-budget random portfolio can replay from stored records. Those two comparisons give the Bayesian, adaptive and joint methods a measured reference point.
